# 胶片抢救任务指挥台

在原有「胶片分镜条核对台」基础上扩展的纯前端本地应用，用于纸质放映胶片抢救任务的事故登记、派工、修复、复检、关闭全流程指挥。

直接打开 `index.html` 即可使用；也可以运行 `npm start` 后访问 <http://127.0.0.1:8137/index.html>。

## 功能

### 抢救看板（五列流转）
登记 → 派工 → 修复 → 复检/待关闭 → 关闭。

- **登记**：多卷片段、事故类型、严重度（轻微/中等/严重/危急）、责任人、涉及片段多选、文字/影像证据、损坏现场确认。
- **派工**：选择修复技师、修复设备与起止时段。技师与设备均按时间区间占用，同一时段重叠会被拦截（边界相邻允许）。
- **修复**：开始修复时先从库存**预留**替换片段/材料（库存 = 期初 + 流水 − 其他单已预留）；任一项不足则整单不开始、零预留。修复成功预留转消耗；修复**失败则整单回滚**——释放全部预留、库存恢复、案例退回派工，并在流转记录留痕。
- **复检**：复检人与修复人不能为同一人（按钮直接禁用，核心层也强制拦截）；不通过退回派工。
- **关闭**：必须**有证据**且**损坏已确认**，复检通过后才能关闭。

### 资源与库存
人员排班占用、设备占用、每项材料/替换片段的库存/预留/可用量与入库。

### 片段核对台（保留原能力）
多卷片段录入、拖拽排序、颜色偏移/破损筛选、试映前核对提醒、导出片段清单。旧版 `zfl17-film-strip-desk` 数据首次打开时自动迁移。

### 离线标签页合并
- 顶栏「离线快照」可导出当前页面快照；在另一个标签页用「合并页面」导入。
- 同一存储下两个标签页也会通过 `storage` 事件实时自动合并。
- 合并基于**向量时钟 + 三方合并**（共同基端 / 本页 / 离线页）：
  - 不同字段的并发修改自动干净合并；
  - 同一字段双方都改时进入**合并中心逐项裁决**，每项可选本页或离线页；
  - 跨页重复登记的同编号案例按重复项二选一，其字段仍逐项裁决；**完全重复的案例只吸收一次**；
  - 证据按内容哈希幂等去重，完全重复的证据只保留一份；操作历史按操作 id 并集；库存流水/预留按 id 幂等合并。
- **同案同操作只吸收一次**：两个离线页对*同一案例*执行了完全相同的派工/预留时，各自生成的预留单、库存流水、流转记录 id 不同但语义相同。合并时按操作语义（案例+物料+数量+状态、案例+物料+变动量+类型、动作+详情+操作人）再做一次幂等去重——相同派工/预留/流水/历史只保留一份，因此小数量不会被算成两次、临界大数量（如库存 5 米两页各预留 5 米）不会被误报为超量。派工相同但材料/数量等确实不同的操作，仍作为两次操作正常合并。
- **合并提交前重校验资源与库存**：两个页面各自合法、合在一起仍可能冲突，因此合并结果落盘前会重新检查：
  - 同一技师在重叠时段被两个案例占用 → 阻止合并；
  - 同一设备在重叠时段被双派工 → 阻止合并；
  - 合并后某项「已预留总量 > 库存」→ 阻止合并（可用量绝不会变负）；
  - 每条冲突都会在合并中心明确列出（涉及人员/设备/时段/案例编号或库存缺口），提交按钮禁用，本页数据**整批不写入**；在任一页面调整派工或预留后重新合并即可。
  - 合法数据（时段错开、库存不超）仍正常自动合并，不弹裁决框。

### 现场保留、撤销重做、导出
- 刷新后保留：当前页签、筛选、搜索、表单草稿、勾选的片段、当前操作员、打开的案例抽屉。
- 任意已提交事务可撤销/重做（按钮或 Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z），最多 30 步；落盘失败的事务不会进栈。
- 「导出事故包」生成当前案例的 JSON 包：案例全字段、证据、片段、预留、库存流水引用。
- 所有写操作都是**原子事务**：先在草稿上校验执行，再一次性落盘；任何校验失败或 `localStorage` 写入失败都会整单回滚，内存与磁盘保持一致。顶栏「⚙ 模拟下次保存失败」用于演练该路径。

## 文件

- `index.html` / `styles.css` — 界面与样式
- `core.js` — 无 DOM 依赖的核心层：数据模型、事务、向量时钟、三方合并、领域规则（`window.FilmRescue`）
- `app.js` — UI 层
- `smoke-core.js` — 核心规则 Node 冒烟测试（`npm run test:core`）
- `smoke-merge.js` — 合并资源/库存重校验的 Node 冒烟测试
- `smoke-same-op.js` — 同案同操作语义去重的 Node 冒烟测试
- `tests/e2e.spec.js` — Playwright 真实浏览器端到端测试（七个主场景）
- `tests/merge-guard.spec.js` — 合并守卫浏览器测试（技师重叠/设备重叠/库存超量/合法合并/闭环回归）
- `tests/same-op.spec.js` — 同案相同派工预留只吸收一次的浏览器测试（小数量/临界大数量/不同操作/闭环）

## 测试

```bash
npx playwright install chromium     # 首次需要
npx playwright install-deps chromium # 系统缺浏览器依赖时（需要 root）
npm test
```

端到端覆盖七个场景：正常闭环、越权复检、资源冲突、库存不足与修复失败回滚、保存失败整单回滚、双页竞争（逐项裁决 + 重复只吸收一次 + 实时自动合并）、刷新现场保留/撤销重做/事故包导出/关闭前置校验。
